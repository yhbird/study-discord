### Python 개발 지시사항
- 현재 디스코드 봇은 호스트 PC Mac에서 코드를 테스트하고 테스트 통과, 데이터 검증이 되면 `restart-bot` bash 스크립트를 실행하여 컨테이너를 배포합니다.
- 호스트 PC는 Mac Mini M1 모델이며 RAM 16GB 모델을 사용합니다. 컨테이너는 docker기반 orbstack을 통해 이미지를 build하고 docker-compose 파일을 실행하여 DB, Kafka 컨테이너 생성을 오케스트레이션합니다.
- python 코드를 작성할떄 반드시 `PEP8` 기준에 맞춰서 코드를 작성해야 합니다. comment와 doc-string에 변경내용을 작성하고 뒤에 날짜를 붙입니다. 예시) `변수를 수정했습니다. (2026-10-04, Sonnet 5.5)`
- 프로젝트 안에 py-compile 등을 실행하여 문법적으로나 import 에러가 발생할 수 있는 부분이 있는지 마지막으로 한번 검증합니다.
- 호출된 명령어를 실행하는 부분은 `commands.py`파일에서 작성하며, 데이터 전처리 및 호출하는 부분은 `utils.py`파일에서 작성합니다.
    - 쉽게 말하자면 `commands.py` 파일에선 디스코드 봇이 작성할 메세지를 작성하는데만 집중하고 데이터가 어디서 가져오고 처리 되는지는 모르고 `utils.py`에만 의존해야 합니다.
    - `utils.py` 파일의 경우 전처리, 데이터 수집 과정에서 추가로, 캐싱, 공통 전역변수를 사용해야 하는 경우에는 service경로에 각자 서비스에서 `const.py`, `resolver.py` 등으로 존재합니다.
    - `command.py` 파일과 `utils.py` 파일은 서비스 마다 각각 개별 `exceptions.py`에서 예외처리롤 가지고 있고, 이 예외처리로 인해 명령어가 실패한 경우 가장 큰 상위 공통 exceptions를 호출하고 실패 메세지를 출력합니다. (`common_exceptions/command_exceptions.py` 참고, 일부 서비스는 아직 리팩토링 작업이 되어 있지 않아 지시사항과 다른 구조를 가지고 있을 수도 있습니다.)
- `command.py` 파일과 `utils.py`파일은 메세지를 작성하는데 string을 변환하거나, `,`문자열 혹은 `억, 만` 단위를 사용해 숫자를 보기 좋게 다듬거나, 이미지를 공통적으로 처리해야 하는 부분은 common 경로에 저장되어 있습니다. 따라서 이곳에서 재사용할 함수 모듈이 있는지 살펴보세요


### Git 사용 지시사항
- 사용자가 요청한 대로 기능 수정, 추가하면서 git 변경사항이 생기게된 경우 commit 메세지 맨 아래에 co-author를 반드시 명시해주세요
- 어떤것이 어떤 문제가 있었고, 무엇이 변경되었는지, 변경으로 인해 영향이 생기거나 체크해야 하는 부분을 3단 구성으로 commit message를 작성하세요
- 현재 작업중인 워크트리에서 사용자의 요청이 있기 전에는 commit, pull, push를 하지 마세요
