### 디스코드 봇 계정 지시사항
- 디스코드 봇은 현재 개인과 지인들만 제한적인 서버에서 사용중이지만, 항상 불특정 다수의 서버, 동시에 많은 요청이 들어온다고 생각하고 이에 적합한 트래픽조절, 요청시간, 중복요청을 방지하기 위한 캐싱 등 다양한 최적화 전략을 사용하고 추천해야 합니다.
- 디스코드 봇 명령어의 `최대 요청시간은 일반적으로 60초`이며, 60초가 지나면 timeout으로 요청이 실패했음을 알림메세지를 보냅니다.
- 디스코드 봇의 명령어 요청은 최소한 1초 이내로 응답을 할 수 있는 수준으로 코드를 작성하는 것을 목표로 합니다.
- 디스코드 봇은 매시간 메모리 최적화를 위해 gc를 실행하도록 자동화 작업이 스케줄링 되어 있습니다.
- 디스코드 봇은 호스트 PC에 VPN를 on/off하는 경우 디스코드 봇도 이에 영향을 받아 컨테이너도 같이 VPN으로 네트워크가 변경됩니다. (현재 대한민국과 일본을 번갈아 가면서 VPN을 설정하고 있습니다.)

### 컨테이너 관련 지시사항
- 항상 검증된 코드와 테스트가 완료된 작업변경 내용을 git commit 혹은 push를 한 경우, `bash restart-bot`을 통해 변경한 내용을 즉시 반영할 수 있도록 합니다.
- 디스코드 봇이 정상적으로 모든 기능을 동작하게 하려면 DB, Kafka 컨테이너가 항상 정상적으로 동작하고 있어야 합니다. 컨테이너 상태를 확인해야 하는 경우 discord-bot-kafka (apache/Kafka:3.7.0), discord-bot-db (postgres:15) 컨테이너도 같이 확인하세요.
- 현재 디스코드 봇은 DB 컨테이너를 바라보며 사용자의 이용 데이터, 로그들을 Kafka가 실시간으로 메세지를 작성해서 적재하고 있습니다. 사용자의 이용 통계 분석, 명령어 병목 확인, 문제가 발생한 시점의 명령어 사용 기록 확인을 위해 수집하고 있습니다.

### 추가 지시사항 작성 및 편집
- 추가적인 지시사항 혹은 코드 내용과 관련해서 세부적인 변경내용, 확인이 필요한 내용이 있으면 DISCORD-BOT.md 파일을 읽고 확인하세요
- 다른 사용자가 클로드 코드를 사용하거나, 개발하면서 변경된 내용이나 지침과 다른 내용이 있는 경우를 위해서 DISCORD-BOT.md 파일 내용을 수정하고 삭제할 수 있습니다.
- 사용자가 문서를 업데이트 해달라고 요청할 때에만 파일 내용이 참인지 확인하고, 거짓이거나 내용이 낡은 경우 수정할 내용을 함께 알려주고 사용자에게 작업 요청을 하세요.

### DISCORD-BOT.md 작성 요령
`DISCORD-BOT.md`는 작업하면서 생긴 기능, 이슈, 정책을 **한 줄씩** 남기는 가벼운 개발 노트입니다. 형식은 참고용이며, 엄격하게 지키기보다 나중에 읽고 이해하기 쉬운 것을 우선합니다.

```
- [F001] 내용을 짧게 한 줄로 (2026-10-04)
```
- `[범주코드 + 번호]`가 항목의 index입니다. 수정이나 삭제를 요청할 때 "F003 고쳐줘"처럼 번호로 가리킵니다.
- 번호는 범주별로 이어서 붙이고(`F001`, `F002`, ...), 삭제된 번호는 다시 쓰지 않습니다.
- 새 항목은 해당 범주 제목(`### F: ...`) 아래의 맨 끝에 추가합니다. 범주 사이는 빈 줄로 구분합니다.

| 코드 | 범주 |
|---|---|
| A | 기능추가 |
| B | 버그 발생 및 해결 |
| C | 에러 대처 매뉴얼 |
| D | 봇의 특징과 정책 변경 |
| E | 기능 수정, 코드 수정 |
| F | 개발 및 설정 규칙 |
| 기타 | 문서 작성 요령 및 규칙 변경

- 새 범주가 필요하면 표에 한 줄 추가하고 바로 사용합니다.
- 토큰, 비밀번호 같은 비밀값은 적지 않고 변수명만 적습니다.
- 범주별 검색: `grep -n '\[B[0-9]*\]' .claude/DISCORD-BOT.md`
